# 한국어 문장 체크리스트

`src/content/content.json`의 한국어 문장을 새로 쓰거나 고칠 때 쓰는 기준이다.
문체 항목은 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 `humanize-korean` 룰북에서
이 사이트에 해당하는 것만 추렸다. 스킬 본체는 `~/.claude/vendor/im-not-ai`에 설치되어 있고
`/humanize` 로 호출할 수 있다.

## 1. 이 프로젝트 고유 규칙 (스킬이 모르는 것 — 반드시 사람이 확인)

- **말투**: 서술형 문장은 `-습니다`체. 짧은 라벨(`label`, `stack`, `role`, `team`)과
  다이어그램 `sub`, 이미지 `caption`은 명사구로 둔다.
- **build 항목 수**: 기능 단위로 잘게 쪼개지 말고 주제 단위로 묶어 프로젝트당 5개 내외.
- **context 필드**: 배경 정보만. 기능·구현 설명을 섞지 않는다.
- **시행착오 금지**: 되돌린 판단이나 실패 서사를 넣지 않고, 만들 수 있다는 사실만 쓴다.
- **결과 서술**: 채택 여부 같은 불리한 마무리 대신 실제로 수행한 활동으로 쓴다.
- **성능 수치**: 면접에서 근거를 대기 어려운 숫자는 넣지 않는다.
- **회사 프로젝트**: 실제 소스 코드를 노출하지 않는다. 의사코드나 다이어그램으로 대체한다.
- **프레이밍**: 문제/해결 구도보다 "무엇을 만들었는가", 그리고 기획이 바뀌어도 버티는
  재사용 가능한 설계를 했다는 인상이 남도록 쓴다.

## 2. 문체 점검 (humanize-korean 룰북에서 발췌)

### 번역투

- `~에 대해/~에 있어(서)/~와 관련하여` → 조사로 직결한다.
- `~를 통해`가 한 필드에 3회 이상이면 `~로`, `~해서`, `~함으로써`로 분산한다.
- `가지고 있다` → `~이 강하다`처럼 형용사·동사로 환원한다.
- `되어진다`, `~지게 된다` 같은 이중 피동은 쓰지 않는다.
- `~에 의해` 피동 → 행위자를 주어로 바꾼다.
- `~에서의/~으로의/~로부터의` 이중 조사는 절로 풀어 쓴다.

### AI 관용구

- `결론적으로`, `이를 통해`, `요약하면` 같은 결산 어휘는 문서 전체에서 1~2회 이하.
- `시사하는 바가 크다`, `주목할 만하다` 같은 의의 과장은 삭제하고 구체 결론으로.
- `다음과 같은`, `크게 세 가지로 나눌 수 있다` 같은 열거 도입구는 빼고 바로 본론.
- `혁신적/획기적/압도적` 류 hype 어휘는 쓰지 않는다.
- `~할 때입니다`, `X를 넘어 Y로` 같은 결말·변환 공식은 쓰지 않는다.

### 접속사·형식명사

- 문두 `또한/따라서/즉/게다가/더욱이`는 대폭 줄인다. 문장 자체가 흐름을 잡게 한다.
- `이는 ~`, `이 점에서` 같은 메타 진입구는 본문에 녹인다.
- `~한 것입니다`, `~다는 것입니다`, `주목할 점은 ~` → `~다`로 직설한다.

### 리듬

- 한 필드 안에서 종결어미가 4문장 연속 같으면 문장 구조를 바꾼다.
  단 `-습니다`체 자체는 유지한다(격식 등급은 바꾸지 않는다).
- 문장이 전부 60~90자면 짧은 문장 하나를 섞는다. 반대로 120자를 넘는 문장은 나눈다.
- `-고,` `-며,` `-지만,` 처럼 연결어미 뒤에 붙는 쉼표는 한 필드에 3회를 넘기지 않는다.
- `~고 있습니다`는 단순 시제로 환원할 수 있으면 환원한다.

### 시각 장식

- 본문에 볼드·이모지·강조 따옴표를 쓰지 않는다.
- 대시(—)로 붙이는 부가 설명이 반복되면 쉼표나 별도 문장으로 나눈다.

## 3. 손대지 않는 것

고유명사·제품명·엔진명·SDK명, 수치와 날짜, 업계 표준 영어 약어(API, IK, FBT, UDP, GAS 등),
다이어그램 `spec` 안의 라벨은 문체 윤문 대상이 아니다.

## 4. 현재 상태 (2026-08-27 점검)

서술형 필드 67개를 룰북 패턴으로 훑은 결과, 번역투·AI 관용구·문두 접속사·형식명사
계열의 S1 패턴은 사실상 검출되지 않았다. 남은 것은 리듬 계열 두 가지다.

- 67개 중 60개가 최장 문장 100자 미만이라 장문이 거의 없다. 의도된 간결함이지만,
  긴 필드에서는 문장 하나 정도를 이어 붙여 리듬을 주는 편이 자연스럽다.
- 연결어미 뒤 쉼표가 `projects[0].builds[0].body`에 4회, `projects[8].builds[1].body`에
  3회 몰려 있다. 새로 쓸 때 이 밀도를 넘기지 않는다.
